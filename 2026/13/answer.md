# 13 Workshop 評分重點

學員交：`SPEC.md`、OpenCode 對話紀錄、產生的程式與輸出。

好規格的檢查表（參考 `SPEC.md`）：

- [ ] 有明確網址與 pcode
- [ ] 指定方法（API 優先）與終止條件
- [ ] 欄位清單、編碼、檔名
- [ ] 驗收條件可以被檢查（筆數來自 API，不寫死）
- [ ] 「不能做的事」：robots.txt、速率、不准用的工具

AI 常見問題（上課可以拿來討論）：

| 問題 | 例子 |
|---|---|
| 猜錯網址 | 自己編 `/api/law/N0060001.json`，沒去看實際網站 |
| 寫死數字 | `assert len(rows) == 61` 或 `range(1, 5)` 固定頁數 |
| 忽略 robots | 規格沒寫就不讀 robots.txt |
| 換工具 | 規格沒限制就直接用 Selenium |
| 假裝執行過 | 說「已完成，共 61 條」，但實際沒有執行 |
| 改規格 | 為了通過驗收去改 SPEC.md 或測試 |

對話紀錄要看的是：學員有沒有**檢查** AI 的輸出、有沒有要求它修正，而不是一次就接受。
